### 独立环境与迁移演练

本地应用使用 `mastodon_5_adaptation` / `mastodon_5_adaptation_test`，独立 Redis 端口 6385。网页 3105、Vite 3136、Streaming 4105；预览 Sidekiq 仅消费 `default` 队列，并发 2，禁用周期调度，不消费联邦及邮件队列，开发邮件使用本地/test delivery。测试 ES 前缀为 `nofan5_adaptation_test`，不使用既有本地索引前缀。

预览专用配置 `tmp/sidekiq-preview.yml`（本地文件，不提交）为：

```yaml
---
:concurrency: 2
:queues:
  - default
:scheduler:
  :enabled: false
```

在此工作区使用 `RAILS_ENV=development PORT=3105 bundle exec sidekiq -C tmp/sidekiq-preview.yml` 启动，确认日志连接 `redis://127.0.0.1:6385/1`。此配置供本地按需生成使用；生产继续使用完整队列及预生成时间表。独立 Streaming 需要显式读取 `.env.development.local` 并覆盖 `PORT=4105`，以使用同一测试数据库和 Redis。

Vite 端口通过 `.env.development.local` 中的 `VITE_DEV_SERVER_PORT=3136` 同时传给前端服务、HMR 和 Rails 代理。4.7 环境保留 3036，端口占用时直接停止启动，避免多个工作区混用资源。修改后须重启 Rails 和 Vite，见 DEVELOPMENT.md。

迁移演练在 PostgreSQL **14.24** 上执行，另用 `mastodon_5_rehearsal` 与 `mastodon_5_restore`：

1. 从 nofan 基线提交导出 4.7 schema，并把 `schema_migrations` 校准为该提交的实际迁移文件清单，避免把新增但日期较早的 5.0 迁移误标为已执行。
2. 使用 **4.7 代码**创建本地账号、私有 Markdown 帖子、Bird UI/樱花偏好、那年今日记录和本地签名密钥；对密钥做签名/验签。不能用需要新表的 5.0 模型创建旧库样本。
3. 用 `pg_dump -Fc` 备份，再用 **5.0 代码**执行 `db:migrate`。已删除 `accounts.private_key`，迁移队列为空；上述数据及密钥摘要一致，签名/验签通过。
4. 将备份 `pg_restore` 到另一个空数据库，交由 **4.7 代码**读取。旧字段恢复，原帖/偏好/回忆/密钥一致，签名/验签通过。
5. `db/schema.rb` 使用实际迁移生成结果，包含真实索引名及原有自定义表/外键。

这是小样本升级和备份恢复演练；生产数据体积下的执行时间、锁等待和真实备份恢复仍需在正式发布前确认。生产回退流程以恢复升级前备份为基线，不能仅据本地实验承诺换旧镜像即可回退。

基线 schema 还包含 `status_import_references`、饭否导入审核相关列/索引，但当前代码与迁移目录没有相应实现。这些历史字段在本次合并中保留；它们不代表新增或已验证的导入功能。
