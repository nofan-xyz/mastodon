# 那年今日：预生成与跨日刷新

## 时间安排

- 所有业务日期和定时任务均使用 `Asia/Shanghai`。
- 23:00 调度次日记录，将各账号任务随机分散到随后 50 分钟；这是入队执行时间窗口，实际完成时间仍取决于队列和数据库负载。
- 00:05 补齐当天缺失的记录，已预生成的账号不重复入队。
- 登录后的状态接口在记录缺失时继续按需入队，不必等批处理。
- 任务参数为账号 ID 和目标日期，跨日执行或重试不会改变目标；兼容升级前仅带账号 ID 的旧任务。
- 生成任务使用 Sidekiq 唯一任务锁，减少同账号、同日期重复入队。已生成记录不会重复计算。

## 数据边界

- 预生成仅查询目标日期之前年份的同月同日，仍按北京时间划分历史时间区间。
- 提前生成的次日记录不会在当天接口中显示。
- 对外展示时重新过滤已删除、私信、转发、非自我回复和不属于该账号的记录；按当前屏蔽规则处理，返回的 ID 列表与实际嘟文同步。
- 记录存在但没有可显示内容时，内容接口返回 200 和空列表，前端显示空状态。
- 后续解除屏蔽等操作可能增加符合条件的内容，但不会回填已生成的快照。

## 前端行为

- 已开启功能时，导航不会因内容仍在生成而消失；明确关闭功能时隐藏。
- 登录后的 UI 只挂载一个状态控制器。生成中每次请求结束后等待约 3 秒再查询，避免并发重复请求。
- 详情页等待生成超过 10 秒时，用“回忆还在整理中”和重试按钮替代骨架屏，后台轮询继续；生成结束后自动显示内容或空提示。新业务日期重新计时，不把未完成的生成当成空数据。
- 状态查询失败时逐渐延长重试间隔，最多 60 秒；状态请求 15 秒超时，内容请求 30 秒超时。
- 北京时间零点切换日期并清除昨日数据；恢复标签页、窗口聚焦和网络恢复时重新检查。
- 隐藏标签页暂停定时请求，重新显示时恢复。旧日期或被后续请求替代的响应不会覆盖新状态。
- 详情页加载失败可重试，先查询状态，再按需读取内容。

## 待生成与空数据的排查

`pending` 表示当日记录尚未生成，`empty` 表示已完成且没有历史内容。记录存在、但内容在读取时被删除或屏蔽规则过滤为空时，也显示空提示。即便没有历史内容，仍需由 `GenerateOnThisDayWorker` 写入空记录，才能结束待生成状态。

持续 `pending` 时先检查对应环境的 Sidekiq 是否运行、是否消费 `default` 队列，以及生成任务是否排队或失败。仅运行 Rails/Vite 不会执行异步生成。生产还需确认 `scheduler` 队列与 23:00/00:05 调度；不要通过在状态接口同步扫描历史内容来绕过缺失的后台进程。

## 发布与验收

无需数据库迁移。发布时需要更新 Web 与 Sidekiq 代码，并重启运行 scheduler 队列的进程以载入新时间表。

重点验证：23:00 预生成、00:00 切换、00:05 漏补、默认开启与主动关闭用户、生成超过 3 秒、跨日旧响应、返回休眠标签页、预生成后删除内容，以及元旦的北京时间年份归属。
