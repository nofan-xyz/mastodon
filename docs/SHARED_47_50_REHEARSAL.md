# 双版本共享数据演练结果（2026-10-26）

状态：隔离演练已启动，正式站与现有 beta 仍保持原部署。尚未切换到正式共库。

## 架构与代码

- 4.7 Web：`codex/shared-data-47`，保留既有前端，补齐新模型、设置键、任务生产端与签名实现。
- 5.0 Web：`codex/upgrade-mastodon-5`，上游仍固定 `559688e153ce3a50b26e327bfe488743da99f3dc`。
- 同一 PostgreSQL、协调 Redis、媒体存储；两个版本使用不同 Rails 缓存数据库。后台任务只由 5.0 执行。
- `NOFAN_SHARED_DATA=true` 启用共存补丁，`NOFAN_SHARED_WEB_ORIGINS=https://beta.nofan.xyz` 明确添加 WebAuthn 来源；canonical 域名与 RP ID 都是 `nofan.xyz`。
- `NOFAN_SHARED_CACHE_REDIS_URLS` 必须列出两个版本的缓存 URL。缓存值不跨版本反序列化，但单项、批量和通配符失效会同时作用到两端。普通缓存隔离不能连登录限流一起隔离：Rack::Attack 使用共同的协调 Redis。

## 隔离边界

演练项目 `/home/mastodon-shared-rehearsal` 使用独立 PostgreSQL、Redis 和仅回环监听的端口 3204/3205/4205；数据库为 `mastodon_shared_rehearsal`。恢复正式站原始 4.7 快照后执行共存迁移，不操作在线正式数据库。演练专用初始化器限制数据库名、媒体桶与 `shared-rehearsal-` 前缀，禁止联邦、邮件、推送、计划任务及其他外部副作用。媒体写入只进入 beta 桶中的演练前缀。

测试用随机账号、密码、TOTP 秘钥和 OAuth 令牌保存在服务器权限 600 的 `results/users.json`，不输出到日志或提交 Git。用户原始会话、OAuth 授权及定时任务只在演练副本中清除。

## 已有证据

- 升级前后原 1,332 个用户的密码摘要、1,410 条本地签名密钥摘要及旧 private_key 摘要一致。
- 共存迁移保留旧 `accounts.private_key`、旧 FASP JSON，同时创建新版能力及账号触达过滤表；不执行破坏性的删列。
- 两端共享 OAuth 身份、密码登录与 host-only Cookie；beta 登录后仍返回 beta 页面。
- 4.7 发帖可由 5.0 读取、编辑；5.0 修改可由 4.7 读取；删除也双向可见。跨 Web 使用同一个 Idempotency-Key 不重复发帖，联邦对象 URL 保持 nofan.xyz。
- 跨版本关注、收藏、转发和资料修改可见；5.0 worker 能分发 4.7 发帖，并送达认证 WebSocket 和通知。
- TOTP 登录成功，同一个验证码跨两个 Web 重放被拒绝。
- 5.0 上传媒体后可由 4.7 发帖使用，匿名媒体域名返回 200；4.7 上传头像可由 5.0 读取。
- 真实两个 Rails 进程中：4.7 先加载旧偏好、5.0 保存新偏好、4.7 再保存其他键，两项改动均保留。
- 站点标题从两端分别写入，另一版本的 Rails 进程均读到新值。原生 API 响应仍可能有其正常的短时缓存。
- FASP 能力跨版本启用、读取及旧 JSON 镜像一致；激活请求使用演练内替身，没有向外部 provider 发请求。
- 一个 5.0 后台消费者，无重试、死信或计划任务；WebAuthn 来源与 RP ID 检查通过。实体安全密钥尚未做浏览器硬件验证。

演练先复现了热关系缓存问题：5.0 拉黑账号后，4.7 仍返回已缓存的未拉黑状态。新增跨版本缓存失效后，同一 HTTP 测试通过。源码单元测试与真实进程检查须同时保留，不能以纯源码测试替代演练。

## 上线前与回退

1. 构建并固定两版镜像 digest，核对源码 SHA、依赖及编译资源。
2. 备份正式站数据库、Compose 与受保护配置；确认恢复路径与短时切换安排。
3. 对正式库仅执行已演练的共存迁移；保留原账号身份、密码、AR/OTP/SECRET/VAPID 密钥与正式媒体桶。
4. 停止旧 4.7 消费者后启用唯一一套 5.0 workers/scheduler，两个 Web 共用数据与协调 Redis；beta 配置独立资源域名，但不使用快照隔离初始化器。
5. 验证线上登录、API、WebSocket、两版资源、队列及邮件/联邦只处理一次后记录正式切换结果。既有 beta 测试数据不回灌正式库，旧快照部署保留作为历史环境。
6. 优先回退 Web 镜像并保留扩展后的数据库及能处理新载荷的 5.0 消费者；不能为了回退页面丢弃切换后新写入的数据。若退回未补丁旧 Web，须刷新其旧设置缓存。禁止 FLUSHALL。
